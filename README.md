# カラーレシピ

実際の絵の具をパレットへ置き、重ねて混ぜ、水で薄め、その配合を保存できる日本語Webアプリです。選んだ色は触れたまま動かすと、待たずに波状へ伸ばせます。作った色は、そのまま「おえかき」と「ぬりえ」で使えます。

[公開版を開く](https://lunaneco.github.io/Colot-recipe/)

## 主な機能

- 赤・青・黄・黒・白・水を、1タップ＝1単位で正確に記録
- 短いタップは真円、押し続けると中心へ量が重なって厚く広がり、触れたまま動かすと選択色をすぐ波状に伸ばして実際の量まで記録
- 指やペンが触れた瞬間から、長押し量と伸ばした地点数に合わせて配合・色・数値をリアルタイム更新
- 水なしでは不透明で輪郭の締まった絵の具、水を置いた部分だけ透明で広がる水彩表現
- Golden Heavy Body Acrylicの共有許可付き実測K/S（400–700 nm、31波長）と単一定数Kubelka–Munkモデルによる減法混色
- 絵の具が重なった場所ごとに局所比率を更新し、表示中の画素色とスポイト地点の配合を保存・再展開
- 水はタップまたはなぞった部分だけへ加わり、離れた絵の具は乾いたまま維持
- 小・中・大の表示サイズ、ドラッグ伸ばし、「すべて混ぜる」
- 配合比、顔料比、HEX、RGB、HSL、透明度、濃さ、推定色名
- 保存パレットへの登録、1回押しで選択・同じ色の2回目で詳細表示、保存レシピを元配合のまま混色材料として再利用、名称変更、複製、削除、並び替え、再展開、Undo／Redo
- IndexedDBを優先した保存と、全ストアの復旧用LocalStorageミラー
- 版付きレシピJSONと、設定・作品・塗り絵を含む全データバックアップ
- 11種類の描画ツール、筆設定、レイヤー、Undo／Redo、自動保存、PNG出力
- 6種類のオリジナル塗り絵、画像読込、枠内全体を1タップで塗り替える機能、ブラシ塗り、漏れ抑制、PNG出力
- PC、タブレット、スマートフォン対応
- キーボード操作、ARIA、色以外の選択表示、Reduced Motion対応

## 色混合アルゴリズム

`lib/paintCalibration.ts` は、Golden Artist ColorsがAndrew GlassnerとEric Hainesに提供し、他者への共有が明記されたHeavy Body Acrylicのスペクトル表を固定データとして使用します。試料は白のLenetaカード上へ湿潤10 milで塗布し、乾燥後6 milをD65/10°条件で測定したものです。収録値は400〜700 nm、10 nm間隔の31点の反射率と、そこから導出された単一定数 `K/S` です。

| アプリの材料 | 測定塗料 | Colour Index |
| --- | --- | --- |
| 赤 | Pyrrole Red | PR254 |
| 青 | Cerulean Blue Chromium | PB36 |
| 黄 | Hansa Yellow Medium（歴史的製品番号1190） | PY73 |
| 黒 | Bone Black | PBk9 |
| 白 | 理想散乱白リファレンス（実測行なし） | — |

1タップは「完成絵の具の相対的1部」です。赤2・青1なら波長ごとの `K/S` 寄与を2:1で加重します。密度や乾燥顔料濃度のデータはないため、アプリ単位をグラムや乾燥顔料質量とは表現しません。

1. 各波長で `K/Smix(λ) = Σ cᵢ(K/S)ᵢ(λ) / Σ cᵢ` を局所の連続比率のまま計算
2. `R = 1 + K/S - √((K/S)² + 2K/S)` で混合反射率へ戻す
3. CIE公式の1964 10°等色関数とD65でXYZへ積分
4. 10°のD65白色点から標準sRGBの2° D65白色点へBradford色順応
5. 指定済み純色を結ぶOKLab基準へ、実測スペクトルが作る色間相互作用を連続的に戻す
6. sRGB色域外はOKLabの明度と色相を保ち、彩度だけを縮めてHEX/RGB/HSLへ出力

従来の合成反射曲線、手動散乱力、赤黄だけの経験的補正は使用しません。`1:1`と`2:2`は同じ色になり、材料の投入順やオブジェクト順でも変わりません。描画用キャッシュは色比率だけを再利用し、透明度、水分比、粘度は画素ごとの実量から必ず再計算するため、薄い縁を過大に濃く表示しません。

指定済みの開始色（赤 `#E60012`、青 `#00A1E9`、黄 `#FFF100`、黒 `#000000`、白 `#f8f3e8`）は表示上の契約として維持します。HEXと実測顔料は別の色定義なので、画面では純色・白混色・黒混色が連続するOKLab表示校正を使います。底層の混合反射率は常に実測K/Sから別途算出され、テスト可能なまま保たれます。

水は顔料のK/Sへ足しません。固有色を保ったまま透明度、濃さ、粘度、広がり、乾燥速度へ作用するアプリ内近似です。広がった顔料は面積に応じて質量補正し、中心の1単位を保ちます。白は理想散乱リファレンスとしてK/Sを下げ、明度と被覆力へ作用します。

### 再現範囲と限界

「赤」「青」「黄」やHEXだけでは実物の絵の具を一意に決められません。同じ表示色でも異なる反射スペクトルを持つため、別メーカー、別顔料、製造ロット、下地、膜厚、乾燥状態、照明が変われば結果も変わります。本アプリの結果は上表の固定プロファイルを基準にした予測であり、すべての市販絵の具に共通する絶対値ではありません。元データは白地が透ける6 milの単色塗膜で、真の不透明層や実測混色チップではありません。単一定数K/Sは顔料ごとの散乱力を分離できず、白は共有ワークブックに実測行がないため理想参照です。したがって「配合比を数学的に忠実に反映する」ことは検証していますが、実物との色差ゼロは主張しません。

また、水による透明な有限膜厚、紙の反射、バインダー移動、乾燥時の色変化は実測校正データがないため、透明度と空間拡散による近似です。sRGB色域外はチャンネルを個別に切らず、OKLabで明度と色相を保った彩度圧縮を行います。採用データ、CIE標準値、共有条件、データ部分がプロジェクトのMITライセンス対象外であることは [`THIRD_PARTY_NOTICES.md`](./THIRD_PARTY_NOTICES.md) に記録しています。

### 局所混色とスポイト

パレットへ置いた各絵の具は1単位のまま記録されます。水なしではチューブ絵の具のように不透明な胴体と締まった輪郭で描き、水が届いた部分だけ透明度と広がりを増やします。絵の具同士が重なった場所では、その地点へ届く各材料の重みから顔料比率を更新します。触れたまま動かした軌跡には選択中の絵の具または保存レシピ色だけを追加し、保存色は元の配合比率を保ちます。「すべて混ぜる」では、操作時点の水を含むレシピ全体をなじませます。

水はタップで1単位、なぞると軌跡へ複数の局所配置として追加されます。全体レシピ欄の水は投入総数、スポイト欄の水分量は調べた地点だけの値です。水を置いても、離れた絵の具の透明度や水分量は変わりません。

保存パレットの色を混色モードで選ぶと、その色が「レシピ色」として材料欄にも現れます。混色パレットを1回タップするたび、保存時の赤・青・黄・黒・白・水を1バッチそのまま加算します。たとえば赤2・青1・水2の保存色を2回置くと、全体レシピは赤4・青2・水4になります。表示用HEXを材料へ逆変換したり、比率を縮約したりしないため、保存した量と割合を保ったまま別の色や水と重ねられます。1バッチは1回のUndoまたは消しゴム操作でまとめて取り除けます。

「スポイト」を選んでパレットをタップ、またはなぞると、マーカー位置の局所量、顔料比率、水分比、色名・HEX・RGB・HSLを表示します。比率は局所配合から計算し、色はその瞬間に画面へ描画されたCanvas/WebGLのRGBAを直接取得するため、光沢や重なりを含む見えている色と登録色がずれません。WebGLを使えない環境では、表示中のCanvas 2D画素へ自動で切り替えます。たとえば赤と黄を同じ強さで重ねた中心は「赤 50.0%：黄 50.0%」となり、赤側へ動かすと赤の比率が上がります。スポイト結果は調査表示であり、全体レシピの投入単位を書き換えません。

「この色を登録」は常にレシピ欄に1個だけ表示されます。スポイト結果を表示したまま押すと、全体配合ではなく、その地点の最新画素色と比率を保った再現用レシピを保存します。局所量は合計比誤0.2ポイント以内を満たす最小の整数レシピへ変換し、最大1,000単位に抑えます。998:2相当の0.2%顔料は顔料間比率を別に検査し、499:1として保持します。水が多い地点でも顔料間の微量成分を失いません。取得したRGBAは `capturedAppearance` として配合とは分けて保存されるため、再読込後も見た目の色を維持しながら、水分比や顔料比などの物性はレシピから安全に再計算できます。保存詳細には「スポイト地点の局所配合」と記録され、「もう一度つくる」で混色パレットへ再展開できるほか、レシピ色として現在の混色へ加えることもできます。顔料のない空白や水だけの地点は、色としては登録できません。

## ぬりえの枠内タップ塗り

「タップで枠内を塗る」は、線画レイヤーを境界として、タップした枠の内側全体を選択色で塗り替えます。以前のブラシ色が残っていても領域を分断せず、同じ枠内をまとめて置き換えます。線は最上層へ残り、線上をタップした場合は塗りません。

「線の感度」で薄い線の認識を、「線のすき間をとじる」で小さな切れ目の補正を調整できます。補正しても閉じられない大きな切れ目がある場合は、ページ全体へ漏らさず塗りを中止します。透明背景のPNGも、透明な余白を線として誤認せず読み込めます。

読み込み時は `recipe` を正本とし、`mixed` の顔料比率、水分比、濃さなどを現在の計算エンジンで再計算します。スポイト色に限り、形式と範囲を検証した `capturedAppearance` からHEX・RGB・HSL・透明度を復元します。版付きJSONは現在 `version: 3` で、`version: 1`、`version: 2` と従来の版なし配列も旧版として移行できます。長押しの重なり量は1操作あたり最大8単位に制限します。ファイル内で同じIDが重複する項目や、範囲外・不正な項目は安全のため個別に除外されます。読み込む色のIDが端末内の保存色と衝突した場合は、新しいIDを割り当てて両方を残します。

保存パレットの色は1回押すと選択状態になり、同じ色をもう一度押すと詳細を開きます。登録・名称変更・複製・削除・並び替え・読込は50段階までUndo／Redoでき、戻した状態も端末保存へ反映されます。

## 保存仕様

データベース名は `color-recipe-studio` です。

| ストア | 内容 |
| --- | --- |
| `colors` | 保存色、レシピ、順番、メモ |
| `settings` | 最後のモード、選択色、最近使った色、混色・描画・塗り絵の設定 |
| `artworks` | おえかきの全レイヤー、選択レイヤー、背景、用紙サイズ |
| `coloring` | テンプレート・読込線画ごとの塗り進捗 |

各保存操作はIndexedDBとLocalStorageミラーの両方へ試行し、少なくとも一方へ保存できた場合は継続します。読込時はIndexedDBを優先し、利用不能・空・破損時にはミラーから復旧します。壊れた保存色が混在しても、検証を通った色は回収します。データは端末・ブラウザごとのローカル保存です。

「全データ保存」は4ストアを版付きバックアップへまとめます。

```json
{
  "kind": "color-recipe-app-backup",
  "version": 2,
  "exportedAt": "2026-07-28T00:01:00.000Z",
  "stores": {
    "colors": [],
    "settings": [],
    "artworks": [],
    "coloring": []
  }
}
```

「全データ復元」は書き込み前にファイル全体を検証し、通常は既存データと結合します。バックアップと同じ色ID・設定キー・作品キー・塗り絵キーはバックアップ側で更新し、バックアップにない端末側データは残します。レシピJSONと全データバックアップは用途と形式が異なるため、それぞれ専用の読込ボタンを使います。

## セキュリティーとプライバシー

- アカウント、解析タグ、広告、外部フォント、外部APIは使用しません。
- 色、設定、作品、塗り絵はブラウザのIndexedDBとLocalStorageへ保存します。
- 読み込む線画はPNG・JPEG・WebP、8MB以下、最大8192px・3200万画素に制限し、固定サイズのPNGへ再描画して位置情報などの画像メタデータを除去します。
- 全データ復元は、外部URL、SVG画像、過大画像、未対応キャンバス、過剰レイヤー、安全でないオブジェクトキーを、保存前にまとめて拒否します。
- 外部送信を止めるCSPとReferrer Policyを `index.html` に設定し、GitHub PagesのHTTPS配信だけを利用します。
- GitHub Pagesでは任意のレスポンスヘッダーを追加できないため、CSPで可能な範囲を防御しています。`frame-ancestors`、Permissions Policy、COOP/CORPなどの独自ヘッダーが必要な場合は、専用ドメインとヘッダーを設定できるホスティングへ移してください。
- 実行時の環境変数や秘密情報は必要ありません。秘密情報を `VITE_*`、リポジトリ、`.env.example` に記録しないでください。

詳しくは [PRIVACY.md](./PRIVACY.md)、脆弱性の報告方法は [SECURITY.md](./SECURITY.md)、公開前の確認項目は [PUBLISHING.md](./PUBLISHING.md) を参照してください。

## GitHub Pagesへの公開

`main`へ取り込まれた変更は、`.github/workflows/pages.yml` が検証済みの `dist/` だけをGitHub Pagesへ配信します。公開先は <https://lunaneco.github.io/Colot-recipe/> です。外部Actionはコミット番号で固定し、公開ジョブには必要最小限の権限だけを与えています。

ローカル版と公開版は保存領域が別です。ローカル版の色や作品を移す場合は「全データ保存」でJSONを書き出し、公開版の「全データ復元」で読み込んでください。

## 操作の補助

- `Ctrl/Cmd + Z`: 元に戻す
- `Shift + Ctrl/Cmd + Z`: やり直す
- `Alt + 1 / 2 / 3`: モード切替
- 混色パレットへフォーカスして `Enter` または `Space`: 中央へ選択材料を追加（保存レシピ色は1バッチ）
- 混色モードの `R / B / Y / K / W / A / E / I`: 赤／青／黄／黒／白／水／消しゴム／スポイト
- スポイト結果の表示中に `← / ↑ / → / ↓`: 調べる地点を少しずつ移動

## 既知の制限

- 顔料モデルは一般的な画材の挙動を狙った近似で、特定メーカーの実測スペクトルを校正したものではありません。
- 保存は端末ローカルで、複数端末間の同期や共同編集はありません。
- GitHub Pagesのプロジェクトサイトは同じ `lunaneco.github.io` オリジンを共有します。制作データの厳密なサイト分離が必要な場合は、このアプリ専用のカスタムドメインを使ってください。
- 筆圧はPointer Eventsで値を提供するペン／端末に依存します。
- WebGLが利用できない環境では、混色面はCanvas 2Dの軽量表示へ切り替わります。
- 読み込んだ線画の線が極端に薄い場合は、領域判定の前に画像側のコントラスト調整が必要な場合があります。
- 大きなレイヤーを多数追加すると、モバイル端末では保存容量とメモリの影響を受けます。
